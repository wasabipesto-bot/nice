# Research report, 2026-11-18

## New research

**Started this morning: near misses as a by-product of the search** (result by about 11:30 UTC).

- The search will almost certainly find no second nice number in the bases it can reach. But
  numbers that miss by one or two digits should exist there: about 0.4 expected with 61 of 62
  digits in base 62, and a few hundred with 60.
- **Today's search discards them.** Its last stage already computes the digits of every
  candidate that reaches it and stops at the first repeat. Counting repeats instead would find
  the near misses whose end digits are clean (over half, by a rough count) for a small cost.
  The wire format and the server already carry a digit count per reported number.
- An investigator is working out exact coverage and yield, building a CPU prototype, pricing
  the GPU change, and checking what the server and site would do with such entries. It would
  be a new feature, so it comes to you as a one-page proposal, not a PR.
- It stops if the cost is over 3 % of a field or the expected yield is under 30 numbers.
- Base 62 is 14 % done and loses about 1.2 % a day.
