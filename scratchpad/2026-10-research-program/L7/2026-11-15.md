## B. Web searches by theme

**Pandigital powers / digits of squares and cubes / restricted digits.** No 2026 paper found.
Nearest items are old and already background: Wu, "Pandigital and penholodigital numbers"
(2403.20304, 2024; squares only, shows no strict pandigital squares in base b when b is odd and
v2(b-1) is even) and OEIS A340501-type entries. Hits are old/background only; nothing new.

**Meet-in-the-middle with carries.** No paper found that combines MITM with digit carries for
squares and cubes. The closest is "Squares with three digits" (arXiv 2112.00444, 2021), which builds
square roots with a restricted digit set by a carry-based recursion. It is pre-window and not a
join; the project's overlap join does not take anything from it. Not new.

**GPU set intersection / compaction / divergence.** Nothing new in the window (see A). Standing
leads from earlier sweeps (GTaP/DAQ 2604.05982, warp-aggregated atomics) are unchanged.

**Subgroup / wave operations in Vulkan and WebGPU.** One relevant platform item: WebGPU
`subgroup-size-control` (the `@subgroup_size` attribute, power-of-2 within adapter min/max) was
approved in the Chromium intent to ship (late June 2026) and is listed under Chrome 151-152 (blog
dated 2026-08-12); Chrome 155-156 notes mention an "experimental subgroup features cleanup". This
predates the window. It bears on the project only for WebGPU-side kernels that rely on a fixed
subgroup width for ballot/prefix-sum compaction. No result for "partial subgroups" or Vulkan
subgroup uniform control flow; that needs a Khronos-sourced search next week.

**GPU shader-compiler bugs (naga, ACO, SPIR-V).** No confirmed new miscompilation report in the
window. Search returned only undated or older forum/issue threads (an NVIDIA forum report of a
wrong branch for a short-circuit `||` in SPIR-V-loaded shaders, undated; an NVIDIA Xid 109 hang
report on a cooperative-vector store path, user diagnosis unconfirmed; a PLDI 2025 divergence-aware
shader-compiler testing paper that found 12 back-end bugs). Context only. Nothing in naga, ACO or
CubeCL tracked here for this window beyond Section C.

**Integer division by constants on GPUs.** Nothing new on GPUs. Nearest item: arXiv 2604.07902
(April 2026, pre-window) revisiting Granlund-Montgomery for 32-bit division by a 33-bit magic
constant on 64-bit CPUs (one multiply plus one 64-bit shift); seen via an abstract summary only,
CPU-oriented. Mesa's `fast_idiv_by_const.h` already documents the GPU form (64-bit multiply-add,
"round down" optimization). No new bearing on the Apple Metal constant-division defect, which the
program already records as fixed in the OS.

**Verdict A/B: no relevant new paper this week.** This is the fifth consecutive null sweep.

## C. Release-note checks

**CubeCL (tracel-ai/cubecl releases page).** Releases: v0.11.0 (6 Oct), v0.11.1 (20 Oct), v0.11.2
(21 Oct), v0.11.3 (22 Oct, marked Latest), v0.12.0-pre.1 (28 Oct), v0.12.0-pre.2 (9 Nov). No final
0.12.0 yet. Items that touch the checked areas (as shown on the releases page; I did not read the
linked PRs, so scope is inferred from titles):
- Optimizer: pre.1 "fix(opt): make simple CSE linear in the operations of a region". This is a
  complexity fix to CSE; the title does not say anything about the atomic-store merge defect.
- Atomics: v0.11.0 "Fix atomics on CUDA again" (#1354, earlier note); pre.1 "report shared-memory
  atomics apart from global ones" (IR reporting feature). Neither names merging of atomic stores.
- Stores: pre.2 "Store: an eager store serves a value the storage refused to write" (#1970). Title
  is ambiguous; it could be adjacent to the merged-store defect or unrelated. Worth reading the PR
  itself (not done here) before concluding.
- Arithmetic fold: pre.2 "fix(ir): a fold by one is not the other operand, for remainder and
  mul_hi" (#2105). Relevant to any kernel using remainder or mul_hi folds (the project's
  division-by-constant paths); a correctness fix in the IR constant folder. Check whether it affects
  kernels the project's tests exercise.
- SPIR-V: v0.11.1 buffer tagging fix when read-only; v0.11.2 "a plane barrier orders the
  workgroup's memory"; pre.2 variable-pointer capability inference. The v0.11.2 plane-barrier
  fix is the most relevant to subgroup-based kernels on the SPIR-V path.
- wgpu: pre.1 "fail instead of waiting forever on a hung device".
- Net: nothing explicitly mentions the atomic-store merging defect. The 10-28 evaluation said
  not to upgrade from 0.11.x and revisit at 0.12; pre.2 is still pre-release, so that stands, with
  the two fixes above (#2105, #1970) as items for the program to read before 0.12.0 final.

**Mesa 26.x (RADV/ACO, RDNA4).** Mesa 26.2.7 was released 2026-11-11 (26.2.0 to 26.2.7 listed; no
26.3.x notes found). Its notes contain no GFX12/RDNA4 entries, no compute-specific RADV change, no
subgroup entry and no integer-division fix. ACO items: "aco: demote exec if condition is all-ones",
"aco/opt_postRA: check quad alignment of sgprs" and "fix split_vector reassign with late kill
operands", "aco: make sure SSBO SMEM loads respect barriers". These are code-generation
correctness fixes in ACO's post-RA optimizer and memory-barrier handling; none is tied to RDNA4
specifically in the notes, but they touch the same compiler the 9070 XT runs. Earlier 26.x notes
seen via search: 26.1.4 "radv: fix setting COMPUTE_DISPATCH_INTERLEAVE on the gfx queue" and
"aco/ra: Fix get_reg_impl() for operand registers"; 26.0.4 a GFX12 VRS draw workaround. Nothing
in 26.x is clearly an RDNA4 compute bug. The 26.2.0 bug list included a RX 9070 XT GPU ring reset
(a game title); fixed status unknown.
