## 1. The change

**Readers and writers of `top_p` / `top_m` / `top_r` / `top_x` on main** (all in `common/src/cubecl_join.rs`):

| where | role | words |
|---|---|---|
| `top_kernel` (both comptime variants: the full launch and `only_clipped` beside the FD kernel) | writes top `g = slot·ntlay + idx` | p, m, r (= `a[0] − pw0`, `e[0] − pw0 + 1`), x (= P mod b^(k2 − f0), seed flag); `top_b[g]` |
| `top_fd_kernel` | writes top `g = slot·ntlay + at + pre` (plane-aggregated append) | p, m, r (= 0, w), x; `top_b[g]` |
| `join_kernel`, batch load | thread u reads top `t = tl[tc + u]` into the shared `t_lo`, `t_hi`, `t_rlo`, `t_rhi`, `t_dm`, `t_id` | m, r, x (6 words) |
| `join_kernel`, `v_part` (only shapes with `v_digits > 0`: small test windows) | the bucket's first top | x lo |
| `check_kernel` | survivor `(t, r0)` → n = P·b^f0 + r0 | p |
| `JoinDevice::read_checked` (tests) | the same on the host | p |
| test `run_tops` (#240's `cubecl_cuda_top_fd_matches_the_top_kernel`) | every kept top of a slot, sorted | p, m, r, x, b |
| `JoinDevice` | four handles of `max_slots · fp.top` bytes, each bound with `2 · max_slots · ntl` words to the top kernels (×2), the join (m, r, x) and the check (p) | |
| `join_plan.rs` `Footprint` | `top: ntl · 8` "each of" the four; `per_slot` adds `4 · top`; `largest_per_slot` and `max_slice_prefixes`' `per_largest` take `top` | |

**The change** (`734899f`): one array `top_rec` of `TOP_REC_WORDS` = 8 words per top, `[8g, 8g + 8)` = P lo, hi; mask
lo, hi; r lo, hi; x lo, hi. Every writer stores the same eight values at `8g + j` (in the same order of statements);
every reader reads word `8t + j` where it read word `2t + (j mod 2)` of array `j / 2`. `top_b` stays its own array (the
fill kernel reads only it). The join's shared layout (`t_lo`, `t_hi`, `t_rlo`, `t_rhi`, `t_dm`, `t_id`) and everything
downstream of the batch load is unchanged. `JoinDevice` holds one handle (`max_slots · fp.top_rec` bytes, bound with
`8 · max_slots · ntl` words everywhere). The footprint: `top_rec: ntl · 32`, `per_slot` adds `top_rec` (the same bytes
as `4 · top`), and `top_rec` takes `top`'s place in `largest_per_slot` and `per_largest`.

- **The plan cannot move.** `top_rec` is 4× the old largest top array and is now the largest per-slot buffer that grows
  with the top layer, but the binding bound it enters never binds first: in `max_slice_prefixes` the survivor bound is
  `list_cap / 8` with `list_cap ≤ budget / 32 ≤ max_binding / 16`, so ≤ `max_binding / 128`, against the binding bound
  `max_binding / 64`; in `JoinPlan::new` the survivor bound is `list_cap / (4·ntl) ≤ max_binding / (64·ntl)` against
  `max_binding / (32·ntl)`. Every run below reports the same `slots` and `plan_mib` on both sides (b62 1e17: 5 slots;
  b62 1e16: 13, 2050 MiB; b60 1e16: 4).
- **Indices.** Every buffer of a layout fits its budget, at most 4 GiB (`JOIN_MEMORY_MAX`), so `8t` stays below 2^30.
- **Two load variants** (brief step 1): **S**, eight scalar indices (the join reads six: words 2–7); and **V**, the
  join binding `top_rec` as `Array<Vector<u32, Const<4>>>` (CubeCL 0.10's name for `Line`) and reading `top_rec[2t]`,
  `top_rec[2t + 1]`. Both compile on CUDA. In SASS (b62), S's batch load is six `LDG.E.CONSTANT` off one base
  (`[R+0x0]` … `[R+0x14]`); V's is one `LDG.E.128.CONSTANT` (words 4–7) and one `LDG.E.64.CONSTANT` (words 2–3; ptxas
  narrows the first vec4 because P is unused). Main's is six `LDG.E.CONSTANT` off three bases.

  DRAM transactions per top draw less power per cycle, and the cap turns that into clock. On a card that is not
  power-limited the gain would sit between the two ratios; not measured (the container cannot lift the cap or lock
  clocks).

## 6. Against L37's estimate (12–16 s, 9–12 % per b62 1e17 field)

- **In time the PR lands at the estimate's low end: 10.9 s per b62 1e17 field, ×1.100** (the estimate: 12–16 s,
  9–12 %, at L37's 150 W cap). b60 1e16 saves 1.3 s of 23.1 (×1.060), where the brief expected the same share as at
  b62.
- **In cycles it is less than half of it:** 1.718·10^11 → 1.644·10^11 SM cycles per b62 1e17 field, 7.4·10^9 saved
  (4.3 %), against the 20.4·10^9 cycles (15.7 s at L37's 1.30 GHz) the ablation put on the second and third arrays.
  The rest of the time gain is clock: the PR's side runs 75 MHz higher at b62 1e17 under the same cap.
- **Why the cycles fall short** (not measured here; the ablation modes were not ported to the record): the ablation
  priced the gathers in a stripped kernel (L37 mode 11 against 13: work items and top batches only), where every warp
  waits on its batch's loads with nothing else to issue. In the full kernel five cubes share an SM and the others' AND
  and walk (54 % of the join, issue-bound) cover part of a cube's gather latency, so taking two sectors out of the
  gather saves less than it cost in the stripped kernel.
- **The two load variants tie** (§2): the six scalar loads from one sector cost the same as one 16-byte and one 8-byte
  load, so the L1 serves the repeat loads and the sector count, not the instruction count, was the cost.
- **Nothing else moved:** the top kernels' time (§4, ±0.8 %), the registers (§5), the plan (`slots`, `plan_mib`), and
  the 1e14 fields (neutral within ±3 %).
